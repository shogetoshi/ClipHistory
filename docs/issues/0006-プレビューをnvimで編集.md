    - ユーザーの config / plugin（`~/.config/nvim`）が読まれること

## 検討メモ

### プレビューを常に nvim にするのは不可

- 一覧を ⌃N/⌃P で流し見する体感を落とすことは許容しない
- 現状の `NSTextView.string` 代入は 1ms 未満
- nvim を毎回起動すると `~/.config/nvim` が lazy.nvim + coc の重量級構成のため 200ms〜1秒
- nvim を常駐させて `edit!` でバッファを差し替える方式でも、`BufRead` 系 autocmd
  （filetype 判定 → treesitter → coc の LSP attach）が毎回走るため、選択の高速移動に
  追従できずちらつく可能性が高い

→ **nvim はオンデマンド起動**とする。ブラウズ中は現状の `previewTextView` のままにし、
`⌘E` を押した項目だけターミナル層を前面に出して nvim を起動する。
これにより起動コストは「編集したい1項目・1回だけ」に限定される。

### 採用方式

`previewBox` の3層目として [SwiftTerm](https://github.com/migueldeicaza/SwiftTerm) の
`LocalProcessTerminalView` を重ね、PTY 上で nvim を起動する
（既存の `previewScrollView` / `previewImageView` の排他切り替えの延長）。

画像アイテムは従来どおり `NSImageView` のままなので、この方式では画像プレビューの
問題が発生しない。

### 実装時の要注意点

- **Esc の奪い合い**: 現状 Esc はパネルを閉じる。編集モード中は全キーを nvim へ流し、
  脱出は nvim が受け取らない ⌘系（`⌘↩` 確定 / `⌘.` 破棄）に割り当てる
- **`windowDidResignKey` の自動クローズを編集モード中は無効化**しないと編集内容が消える
- **プレビュー幅 45%（約 300pt）は nvim には狭い**。編集モード中は全幅へ拡張する
- **`HistoryStore.loadFullText(itemID:)` の追加が必須**。既存の
  `loadPreviewText(itemID:maxCharacters:)` は 4,000 文字で切るため、
  そのまま書き戻すと末尾が欠落する
- **書き戻しは `public.utf8-plain-text` の1表現のみ**。元項目が RTF+テキストを持っていても、
  プレーンテキストを編集した時点で他表現は整合しないため
- **編集内容の取り出しに msgpack 実装は不要**。`nvim --listen <sock>` で起動し、
  `nvim --server <sock> --remote-expr 'writefile(getline(1,"$"), "<out>")'` を
  `Process` で叩けばよい（nvim 自身を RPC クライアントとして使う）
- **一時ファイルのセキュリティ**: クリップボードには認証情報が入りうる（`skipConcealed` の所以）。
  0700 のセッションディレクトリに置き、読み取り直後に削除する
- **GUI アプリの PATH には `/opt/homebrew/bin` が無い**。nvim の起動はログインシェル経由
  （`/bin/zsh -l`）にするか、絶対パスを設定項目にする
- **未検証リスク**: `.nonactivatingPanel` 上の SwiftTerm での日本語 IME、
  および SwiftTerm 追加による「外部依存ゼロ」という現行方針の変更

### 却下した案

- **外部ターミナルで nvim を開き、終了を検知して読み戻す**: 半日で作れるが別ウィンドウが開く
- **`nvim --embed` + msgpack-RPC で自前グリッド描画**（VimR / Neovide 方式）: 工数が数週間規模
- **アプリ全体を TUI 化**: `changeCount` ポーリング常駐・Carbon グローバルホットキー・
  `previousFrontmostApp` へのフォーカス復帰はネイティブでしか成立せず、
  結局「常駐デーモン＋TUI フロント」の2プロセス構成になる。
  画像プレビューも sixel / kitty graphics protocol 依存になり、既存の UI 資産も破棄になる

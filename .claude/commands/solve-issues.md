# 複数Issue一括対応ワークフロー

対象Issue番号: `$ARGUMENTS`

このセッションが**総指揮官**である。総指揮官は「どのIssueを今回まとめて対応するか」を決めるだけであり、
**実装・コミット・マージは行わない**。各Issueの対応は `solve-issue` の手順をそのまま実行する
サブエージェントに委譲する。総指揮官が直接コードを書いてはならない。

## 0. 前提確認

1. 引数のIssue番号をすべて4桁ゼロ埋めに正規化する（`17` → `0017`）。引数が空なら中断して報告する。
2. `git status` が clean であることを確認する。未コミットの変更があれば中断して報告する
   （勝手に stash/commit/破棄をしてはならない）。
3. 各Issueについて `docs/issues/0017-*.md` 形式のファイルを探し、**全文を読む**。
   見つからないIssue番号は「対象外」として記録し、残りで続行する。
4. 各Issueの `依存` 欄を確認する。未完了の依存があるIssueは「対象外」として記録する。
   ただし、その依存先が**今回の引数に含まれていて、かつ先に処理される**場合は対象に含めてよい。
5. `docs/design.md` の 13.3（禁止事項）と、各Issueが `関連` で挙げている節を読む。

## 1. 変更箇所の推測

Issueごとに、**コードを変更せずに読むだけ**で影響範囲を推測する。必要に応じて
`Grep` / `Glob` / `Read` や、探索が広くなる場合は `Explore` サブエージェントを使う。

各Issueについて以下を洗い出す。

- **変更ファイル（確度・高）**: ほぼ確実に編集することになるファイル
- **変更ファイル（確度・低）**: 波及して触る可能性があるファイル
- **共有ポイント**: 設定ファイルのスキーマ、共通の型・プロトコル、キーバインド定義、
  レイアウト計算など、複数Issueが同じ箇所を書き換えうる部分

推測結果は「Issue番号 → ファイル一覧」の表としてまとめる。

## 2. 衝突しない組み合わせのピックアップ

以下のいずれかに当てはまるIssueの組は**衝突する**とみなす。

- 同じファイルの同じ関数・同じ構造体・同じ定義を書き換える
- 共通の型・設定スキーマ・キーバインド表など、同一の共有ポイントを両方が変更する
- 一方の完了条件が他方の実装内容を前提にしている（順序依存がある）

判定の上で、**衝突しないIssueの最大の集合**を選ぶ。同数で選択肢が割れる場合は、
Issue番号の小さいものを優先する。

選外にしたIssueは、**理由（どのIssueのどの箇所と衝突するか）を明記して**リストに残す。
勝手に「衝突しそうだからやめる」と黙って落としてはならない。

判定に迷う場合は**衝突する側に倒す**。取りこぼしは次回実行すれば済むが、
衝突したまま走らせると手戻りが大きい。

ピックアップ結果（対象・選外・その理由）をユーザーに提示する。承認待ちは不要、そのまま §3 に進む。

## 3. 逐次実行（サブエージェントへ委譲）

対象Issueを**Issue番号の昇順に1件ずつ**処理する。並列実行は禁止（同一ワークツリーを共有するため）。

1件ごとに以下を行う。

1. `Agent` ツールでサブエージェントを起動する。
   - `subagent_type` は `general-purpose`、`model` は**指定しない**
     （指定しないことで、このセッションと同じモデルを引き継ぐ）。
   - プロンプトには「`.claude/commands/solve-issue.md` を読み、その手順を Issue `0017` に対して
     最初から最後まで実行せよ」と明示する。サブエージェントはIssue本文を持っていない前提で書く。
   - 併せて以下を伝える。
     - 「solve-issue.md の手順を省略・改変しないこと。§6 のアプリ再起動まで必ず実行すること」
     - 「対象は指定したIssue 1件のみ。他のIssueには一切手を出さないこと」
     - 「コード編集は solve-issue.md の指示どおり `minimal-code-editor`（Sonnet）に委譲すること」
2. サブエージェント完了後、総指揮官が以下を確認する。
   - `git status` が clean に戻っている
   - `git log --oneline` に該当Issueのコミットとマージコミットが積まれている
   - `git diff` で、**選外にしたIssueや他のIssueの領域まで変更が及んでいない**こと
   - `make build` と `swift test` が緑であること
3. 上記のいずれかが満たされない場合、**次のIssueに進まずに中断**し、状況を報告する。
   総指揮官が自力でリカバリしようとしてはならない。

## 4. 報告

すべて完了したら、以下を簡潔に報告する。

- 今回対応したIssueの番号とタイトル、および結果（完了 / 失敗）
- 選外にしたIssueと、その理由（衝突相手・未完了の依存・ファイル不在など）
- 積まれたコミットの一覧（`git log --oneline` の該当範囲）
- 実機確認が必要な項目（キー操作の動作など、自動テストで担保できないもの）
- 次回このコマンドを実行するときに残っているIssue番号
